SPEC

文档审查循环

用固定快照、合同覆盖和按缺陷家族修复，让跨合同文档的重复审查更快、更可靠地收敛。

SKILL.md 更新于 2026-08-11 ~7 分钟阅读

必须使用正式审查引擎

每一轮都必须通过宿主平台的正常技能调用方式运行 ce-doc-review。不能复制、改写或自行实现它的角色选择、派发、汇总、问题分类、自动修复、交互模式或跨模型逻辑。

这个技能产出什么

项目内容
结果处于某个指纹状态的产品文档：对它做一次全新的全量 ce-doc-review 门禁，返回零重大问题、零文档改动修复。外加一份收敛信封。
下游消费者发起这次审查的用户或调用方。
完成条件成功信封；或者 Non-converged，且信封每个字段都已填写，包括阻塞原因。
要点

核心不是“多审几轮”，而是先固定证据，再按缺陷家族修复，最后用一份完全没再变化的最终快照证明收敛。

开始前设置

每次调用只运行一次下面的 setup，而且必须在派发任何子代理或子技能之前运行。把 SKILL_DIR 设为刚读取的 SKILL.md 所在目录的绝对路径；按顺序探测可执行的 node 或 nodejs，并把结果存入 NODE。整段命令必须原样单独执行：不能管道过滤、截断、重定向或拆分。没有可用 Node 运行时时继续技能的正常行为，并记录 setup 失败。

SKILL_DIR="<刚读取的 SKILL.md 所在目录的绝对路径>";
NODE="$(for c in node nodejs; do command -v "$c" >/dev/null 2>&1 && "$c" -e '' >/dev/null 2>&1 && { echo "$c"; break; }; done)";
if [ -n "$NODE" ]; then
"$NODE" "$SKILL_DIR/scripts/context.mjs" || echo "context script failed; continue with the skill's normal behavior";
else
echo "no Node runtime; continue with the skill's normal behavior";
fi
  • 输出应以 === skill context 开头，以 CE_CONTEXT_END 结尾。
  • 如果两个标记中恰好只出现一个，原样重跑一次。
  • 其他情况都不能在同一次调用中再次运行。
  • 脚本输出与本技能的提问规则冲突时，以本技能为准；例如 mode:non-interactive 下不能提出阻塞式问题。

参数转发：只剥循环自己的参数

调用 ce-doc-review 前，剥掉 max-work-units:N 和调用者给的文档路径；但必须始终传 mode:non-interactive 和临时快照路径。把 mode:non-interactive 一起剥掉会让每一轮变成交互式，破坏整个循环的前提。

完整工作流

先从当前 SKILL.md 所在目录解析并读取 references/loop-protocol.md，然后按顺序执行。文件缺失或不可读时，返回 Non-converged，写明 loop_protocol: unavailable 和实际原因。正式 ce-doc-review 只能通过宿主的可调用技能机制启动；这是内部调用通道。/ce-doc-review 和 $ce-doc-review 只属于面向用户的交接文本，绝不能通过 shell、终端、命令解析器或普通文本派发来执行。若误执行后收到 Unknown command，应记录 ce-doc-review: invocation_adapter_error；这不能证明技能未注册。只有可调用机制不存在或明确报告技能不可用时，才记录 skill_unreachable。通用任务、内联角色审查或自制审查都不能替代正式技能。

内部调用和用户交接必须分开

可调用机制明确不可用时记录 ce-doc-review: skill_unreachable；命令解析器拒绝 slash/dollar 形式时记录 ce-doc-review: invocation_adapter_error。两种情况都要返回 Non-converged，并打印用户可直接复制的调用块 /ce-doc-review mode:non-interactive <product-path>（仅 Codex 用 $ 前缀）。这个块只用于输出交接，循环本身不能执行它，也不能降级成跳过审查继续运行。

0

Wave 0：冻结输入并建立覆盖模型

冻结原始 Markdown 字节并记录指纹。盘点所有规范性陈述、明确要求、合同、交叉引用和证明义务。只有当它们共享同一权威来源、生命周期和证明边界时，文档才算单合同；否则算多合同。

始终建立 Contract Matrix，把每个盘点项映射到单元格；任何未映射项都是阻塞项。多合同文档还要建立 Change-Impact Graph、稳定纵向切片和证明义务；单合同文档在出现跨合同边或相邻修复影响时再补这些结构。

1

Pass 1：在一次性快照上做正式审查

把冻结字节写入一次性快照，调用 ce-doc-review mode:non-interactive <snapshot-path>。收据必须包含两个指纹、已选择和已完成的审查者、失败/超时/格式错误审查者、文档改动修复数量和终止状态。

调用者计算冻结快照到结果快照的精确差异，并把每个变化的 hunk 按 section 归属到某条 Applied N fixes 记录。只有全部核对一致时，才提交产品路径。缺陷按两类分流：完整性失败丢弃快照且绝不碰产品路径；覆盖缺口可以提交已验证字节，但这一轮不算干净轮次、不能用于收敛。可选跨模型同伴失败两类都不属于，只作报告。两种情况都照样消耗一个工作单元。

2

Pass 2：按缺陷家族集中修复

只处理引用证据和章节标题仍与已验证结果快照相符的问题。每个缺陷家族开始前，确认产品路径仍匹配最新指纹；在一次性快照中暂存机械性改动，并记录完整前后差异。

只有保持产品行为、范围、优先级和既定决定不变的证据支持型机械改动可以自动提交。涉及行为、范围、优先级、产品形态或既定决定的差异必须由用户明确决定。提交后重新计算指纹，并刷新或重验全部适用覆盖工件。

3

后续轮次：先关邻域，再做全量门禁

先用聚焦证据检查关闭受影响切片及图上相连的邻居，然后在新的临时快照上运行正式的全量 ce-doc-review 门禁。正式子技能没有“只审一个切片”的调用契约，局部检查不能冒充正式审查轮次。

4

最终门禁

按 references/loop-protocol.md 的「最终收敛门禁」执行。通常需要一份全新的全量临时快照审查；如果 Pass 1 一处修复都没应用，它已经审过最终字节，可直接充当门禁。只要结果指纹不是那个未变化的最终指纹，就开启一轮修复周期，并要求再做一次最终审查。

交互规则

  • 记录 ce-doc-review 已经执行的 safe_auto 改动，绝不能再应用一次。
  • 交互模式遇到未解决的 gated_auto、manual 或产品决定时，使用平台的阻塞式提问能力；不可用时提供有限编号选项并等待。
  • 运行时不能暂停，或处于非交互模式时，不猜答案：保留阻塞项并返回 Non-converged。
  • 必需进程内审查者失败、超时、格式错误，或调用者收据缺字段，都是不可豁免的覆盖阻塞项。

接受剩余风险的边界

accepted_residual 只能关闭它明确点名的矩阵单元格、图边、邻域、切片或证明义务。它必须绑定当前指纹，并写清受影响合同或证明、影响边界、负责人、到期时间或复审触发条件，以及失败时如何保持关闭。

工作量熔断器

max-work-units 防止无限循环，不是质量合格线。一个工作单元等于一次全局 ce-doc-review 轮次，或一次缺陷家族修复周期。因校验不一致而被丢弃的轮次或周期，同样消耗它那一个单元。每次开始前检查剩余额度。

要点

最后一个允许的工作单元可以正好完成最终门禁并成功收敛；只有额度耗尽且最终门禁仍未成功时，才返回 Non-converged。

失败时必须使用 Non-converged 信封。审查者超时、审查后又修改文档、矩阵单元格仍开放，或手动决定未解决，都不能描述为“已收敛”。

常见错误

错误做法正确做法
每次小改动后立刻再跑整份文档审查先关闭发生变化的 Remediation Neighborhood
一次零发现就算完成确认审查的是最终未变化快照，而且审查者覆盖完整
把 ce-doc-review 内部逻辑复制进来调用正式子技能
为了快，自动替用户做手动、安全或产品决定交互式询问，或保持 Non-converged
把 max-work-units 当质量阈值只把它当熔断器
用修复数量或严重程度下降证明完成关闭矩阵单元格、图边、证明义务和最终快照覆盖

危险信号

听到这些话就停下来检查证据

  • “再跑一轮全量审查应该就够了。”
  • “零发现以后只改了一点点。”
  • “失败的审查者大概也会同意。”
  • “计划已经很详细，准备工作可以省。”
  • “工作量上限到了，所以就算完成吧。”

除非最终门禁真的通过，否则返回 Non-converged。
