# Pipeline mode (`mode:pipeline`)

### Pipeline mode (`mode:pipeline`)

Same tick engine, three deltas:

1. **Delegates run non-interactively.** Invoke `ce-resolve-pr-feedback mode:pipeline` for comments and `ce-debug mode:pipeline` for CI; collect their structured results (fixes + residuals). Never ask the user anything.
2. **Bounded stop, not merge-ready.** Once no actionable backlog remains, take the first applicable outcome:
   - **Success:** CI is clean (`all_checks_ok` — every check terminal, none failing, and at least one observed), GitHub reports a known clean merge state (`mergeability_certain` and `merge_state_status == "CLEAN"`), `open_needs_human == 0`, and `base_ref_blocker`, `stack_blocker`, `branch_currency_blocker`, and `unrequested_base_merge` are null. Report success only when those exact gates hold.
   - **Decision handoff:** if `open_needs_human > 0` and no autonomous work remains, return `{ status: "needs-human", checks_terminal, fixes_applied, residuals: [...] }` immediately without waiting for human input or the time budget.
   - **Budget handoff:** if a fix, round, or time budget is hit, return with residuals.

   Continue any independent stream that can still make autonomous progress. A terminal-but-red check that `ce-debug` marked dispatched but left failing (`diagnosed-no-fix`/`needs-human` → `has_failing_checks` stays true), a racing, pending, or unproven current-base identity, unknown or non-clean merge state, manager-stale/unknown target, an open/claimed/parked current currency item, or an empty `statusCheckRollup` right after PR creation (`checks_present` false — Actions has not created check-runs yet, not that CI passed) is a residual, not a pass. Never wait for the merge-ready settle window or human approval. Under `posture:stack-land`, when the success gates hold, execute Step 3's stack-land land step before treating the layer as pipeline success or advancing; a just-landed MERGED outcome continues the pipeline on the next open non-draft needing work rather than ending the invocation.
3. **Native residual surfacing + structured return.** Needs-human review threads stay open. Preserve each resolver-produced typed residual unchanged, render it immediately under `## Needs your decision`, and return it to the caller. The decision handoff returns `status: "needs-human"`; it never returns success. Anything with no thread home — CI you could not fix after budget, a `needs-human` from `ce-debug` — goes into **one run-report PR comment** (a point-in-time narrative), never a PR-body section.

## Pipeline stop

**In `mode:pipeline`, use the bounded pipeline stop** (Step 1's Pipeline-mode delta 2) once no actionable backlog remains. Report **success only when `all_checks_ok`, `mergeability_certain`, `merge_state_status == "CLEAN"`, `open_needs_human == 0`, `base_ref_blocker` and `stack_blocker` are null, `branch_currency_blocker` is null/current currency is clear, and `unrequested_base_merge` is null**. If `open_needs_human > 0` and no autonomous work remains, return `{ status: "needs-human", checks_terminal, fixes_applied, residuals: [...] }` immediately without waiting for human input or the budget. Otherwise keep working independent streams until they clear or a budget ends the run with residuals. A terminal-but-red check, an unrequested base merge on the head, racing/pending/unproven current-base identity, unknown or non-clean merge state, manager-stale/unknown target, open/claimed/parked currency item, or empty rollup is not success. Skip the merge-ready settle window and human approval. The terminal and blocked conditions still apply.
