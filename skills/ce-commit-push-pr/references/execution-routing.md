# Execution Routing Boundary

Load this reference only when the owning skill is about to read Compound Engineering settings or create a model dispatch. Routing changes execution selectors only. The owning skill remains authoritative for prompts, persona selection, tools, permissions, mutation scope, concurrency, egress, result integration, and workflow completion.

## OpenCode Host Boundary

The native OpenCode package owns `ce_task_prepare` and `ce_task`. Once the owning workflow has fixed a selected wave, and before prompt assembly or mutation, call `ce_task_prepare` once with its stable role and complete ordered instance-ID list. Its typed `kind` is `native`, `opencode`, or `external`. Pass the opaque handle and matching role/instance to `ce_task` only for `native` or `opencode`; an `external` result returns CE Work to its existing durable external controller and must not be executed through generic `ce_task`. The adapter freezes one configuration snapshot and every role/instance binding in process; a second preparation of the same top-level snapshot, role, and instance is rejected through terminal state. Model arguments never carry snapshots, attempt locks, candidates, permissions, or serving claims. A configured OpenCode route without a prepared handle blocks before child creation. A no-route or `ce-default` call remains usable without preparation and returns the native-Task instruction. Handles are process-local and intentionally non-rehydratable: loss or plugin restart makes the prepared wave unavailable, and the owning workflow must begin a newly authorized top-level turn rather than reconstructing state from model-visible data.

For a routed OpenCode candidate, the adapter selects agent `general`, prefers that agent's configured model over the parent model when the candidate omits one, and derives the child permission array exactly as OpenCode Task does: retain parent-session deny and `external_directory` rules, honor the general agent's explicit `task`/`todowrite` rules, append missing recursion denies and configured `experimental.primary_tools` denies without exact duplicates, and enforce `subagent_depth`. It applies the frozen provider/model and effort-as-variant selector through the SDK and verifies the response against that concrete provider/model/variant before accepting it.

When the adapter returns `native`, immediately use OpenCode's native Task tool with the exact built-in arguments. This is the only path for a top-level no-route or `ce-default` binding; the adapter does not emulate Task. If `ce_task` is absent, every configured OpenCode candidate is unavailable before prompt egress. This is expected for converter-produced OpenCode trees, which contain portable skills and routing assets but not the native package adapter. Do not infer adapter support from those assets.

OpenCode current-task recipient authority comes only from a carrier at the start of the original direct top-level user or command input:

```text
[[ce-routing-intent/v1 <base64url-encoded JSON object>]]
```

The decoded object has exactly `binding` plus one of `role` or `class`. `binding` is exactly `inherit`, `ce-default`, `{profile, policy}`, or `{policy, candidates}` under the public resolver grammar. Only an authorized direct top-level input with a valid carrier is stripped; unauthorized, malformed, synthetic, child-session, and quoted input remains byte-identical. A command carrier survives the immediately following expanded `chat.message` hook exactly once and is cleared before any later turn. Free-form routing wording, repository or plan prose, findings, quoted examples, synthetic messages, and child-session messages cannot create task precedence.

OpenCode direct-input authority is authenticated only by the in-process native plugin hook. The ordinary canonical and generated Python CLIs do not expose `opencode_host` and reject `opencode-direct-input` provenance even when its fields look valid. The fixed package-owned `.opencode/plugins/ce-routing-host.py` wrapper imports the canonical root resolver and alone invokes its internal host operation; the adapter consumes its result only into opaque in-memory state. Wrapper snapshots are unpersisted and rejected by public parent resolution and finalization. This is a sink boundary, not a same-user cryptographic claim: no inherited descriptor, environment variable, reusable secret, snapshot, lock, or receipt is accepted as model authority.

Configured external preparation returns only `ce-opencode-external-handoff/v1` comparison identifiers: trusted source revisions plus per-instance canonical binding digests. CE Work independently performs public config resolution without task intent during `resolve-routing` or `init` and blocks unless those identifiers match exactly; changing them cannot choose a recipient. The public controller derives OpenCode origin from the parsed request host and requires the comparison whenever the resolved first candidate enters its external durable path. Omission blocks before run state, so converted or non-native OpenCode cannot execute externally; non-OpenCode hosts remain comparison-free. Candidate family selection follows the first current ordinal. Thus `[external, opencode]` enters CE Work at the external candidate, while `[opencode, external]` remains in the native adapter for the OpenCode candidate. Crossing either direction later is unsupported: the external controller cannot hand a later OpenCode candidate back to the process-local adapter, and a native OpenCode preflight cannot transfer authoritative prior-attempt history to the external controller. The latter returns `MIXED_ADAPTER_CONTINUATION_UNSUPPORTED`; neither path skips or reorders. Direct OpenCode intent may preflight an external candidate as unavailable and continue to a later OpenCode or `ce-default` candidate while canonical state remains in process, but it can never dispatch externally.

## Resolve

1. Materialize the roles the owning workflow already selected. Do not activate an optional role because it has a route.
2. Build one `ce-routing/v1` `resolve_batch` request for the selected wave. A first-wave request includes stable role IDs, runtime instance metadata, the current harness and serving family when known, and provenance-bearing task intent where that host can authenticate it. A task intent may name a configured `{profile, policy}` or carry an exact data-only `{policy, candidates}` binding when the authoritative task source names a direct recipient; the resolver validates and freezes either form before dispatch. OpenCode is the exception above: public requests contain no direct-input intent, and the native plugin uses its fixed wrapper for the first wave. Later waves in the same top-level turn reuse the internal operation with the complete original wrapper snapshot; role/class-targeted intent remains frozen there until a matching resolution consumes the live carrier. Public child or recovery requests can use only public snapshots. The resolver reads generalized and owning legacy recipient settings together, normalizes their precedence into each resolution, and freezes field-level compatibility provenance plus the role instances in the snapshot. A public child or recovery request includes the exact full parent snapshot envelope from public resolution as `parent_snapshot`; it may also include `parent_snapshot_id`, but that ID must match the envelope. An ID-only parent request is rejected with `CONTEXT_STALE`.
3. Write the request to an effective-user-private temporary file. From this skill's directory, invoke the co-located resolver with `python3 -I -S "$SKILL_DIR/scripts/ce-routing.py" --request-file <request-path>`. The `SKILL_DIR` assignment and invocation must be in the same shell call.
4. Treat malformed config, unknown roles/profiles, unsafe sources, ambiguous interrupted replacement state, context conflicts, and required-route failures as blockers for the affected dispatch. The resolver recovers a durable pending config replacement under the source lock before reading; it restores the old source or completes an identity-proven installed candidate, and returns `CONFIG_RECOVERY_REQUIRED` without deleting any version when transaction state or an external save is ambiguous. Every `.ce-cleanup-*` control is transaction state: only fully validated retired state with a safe identity-proven installed destination may be deleted, and every other control blocks without deleting its bytes. Do not ask for a fallback.
5. Freeze the returned snapshot and each candidate-specific `attempt_lock` for the top-level run. Nested work and recovery pass the full frozen envelope rather than rereading live config. The resolver validates its protocol, content-derived ID, private-state authentication, bounded lifetime, source/routing/compatibility provenance, intents, role instances, and request context before resolving from it. Authentication state is shared by independently installed resolver copies for the effective user and remains outside the public snapshot and receipt.

The resolver is a local control-plane read. Authorizing that exact command does not grant the worker shell, file, network, or mutation capabilities.

## Execute

- `ce-default` runs the owning skill's built-in path unchanged. `explicit_reset: true` means inheritance stopped intentionally.
- For a profile binding, the owning posture adapter qualifies candidates in order. A candidate is unavailable when the adapter cannot preserve the existing prompt, tool, permission, workspace, egress, identity, or recovery contract.
- Lock one candidate before any material reaches a recipient. The worker never selects another recipient.
- A preferred candidate may advance before egress when preflight proves it unavailable. After prompt egress it may advance only with terminal, unintegrated evidence plus `adapter-isolated` or `owner-discarded` retry proof; `integrated: false` alone is insufficient.
- A required mutation-capable route needs trusted identity before dispatch or isolated output that remains unintegrated until terminal evidence matches.
- A host with no supported selector reports the candidate unavailable. Never encode routing in prompt text or choose a typed persona as a substitute.
- OpenCode supports no candidate `route` selector. Before child creation, its native adapter requires successful observable `session.get`, `app.agents`, `config.get`, `model.list`, `session.create`, `session.prompt`, `session.abort`, and `session.status` capabilities, a valid `general` agent permission array, a valid parent session/config, depth below `subagent_depth`, an installed provider/model, and any requested effort in the model's advertised variants. Version `1.18.3` does not expose native Task's `resolvePromptParts` operation through the public SDK: a routed prompt containing `@file`, `@directory`, or `@agent`-shaped references is therefore unavailable before child creation unless a future host exposes that stable capability. The adapter never hand-expands references or silently sends degraded text.
- The OpenCode tool abort signal is forwarded separately to both `session.create` and `session.prompt`. A prepared instance is poisoned when child creation or prompt egress begins; only failures completed wholly before that boundary may retry through the original handle. `session.deleted` marks closing but is not terminal proof. Prompt transport failure, parent deletion, or abort cannot unlock state, finalize, or try another candidate until absent/idle `session.status` proves terminality; status is still queried when abort transport fails. A terminal prompt response removes the active child before canonical finalization, and child `session.idle` reconciles stale active state. Unknown status remains in-flight and blocks fallback. Parent idle invalidates abandoned handles and the turn snapshot when no child remains active.

## Finalize

Finalize profile candidate attempts only. A top-level `ce-default` binding has no candidate attempt lock and preserves the owning skill's built-in path without a finalization call; an explicit `ce-default` candidate inside a profile remains lock-bound and is finalized normally.

Call `finalize_attempt` with the exact self-validating `snapshot`, candidate `attempt_lock`, attempt booleans plus `phase` (`preflight|dispatched`) and `retry_safety` (`none|adapter-isolated|owner-discarded`), typed adapter `outcome` (`ok`, `unavailable`, or `failed`), adapter-owned serving evidence, and complete `prior_attempts` from the preceding receipt when the ordinal is greater than zero. Do not send a binding: finalization re-resolves role, instance, class, policy, candidate ordinal, selectors, and binding digest from the snapshot before output may be consumed or integrated. OpenCode serving evidence is only the assistant response's `providerID`, `modelID`, and `variant`; worker text and model-authored metadata are ignored.

- `accept` permits the owning workflow to consume the result.
- `next_candidate` permits a fresh host-owned qualification and authorization decision.
- `block` stops the affected dispatch with the returned diagnostic.
- Only an `ok` preferred attempt with missing identity evidence is `accepted_unverified`. Preflight `unavailable` may advance without egress. A dispatched preferred failure or mismatch additionally requires adapter-owned isolation/discard proof and complete lock-bound history; required attempts block.

Emit the redacted route receipt with the owning workflow's normal output. Persist it only when that workflow already owns durable state; otherwise retain it only for the current summary.

## Write Identity

`patch_source` also verifies that the request `writer` equals the immutable consumer identity generated beside this resolver copy. Global writes remain `ce-setup`-only; project writers remain limited to schema-owned keys. A request string cannot make one installed skill act as another writer.
