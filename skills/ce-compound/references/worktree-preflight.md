# Worktree preflight

Run this after the eligibility and mode checks, before Artifact Root, research, scratch writes, or any documentation edit. The bundled `scripts/prepare-worktree.py` owns Git classification, task identity, worktree creation, and resume. Use an explicit `ticket:ABC-123` token when present, or an unambiguous issue ID from the current task; accept only an ASCII ticket matching `^[A-Za-z][A-Za-z0-9]*-[0-9]+$`. Otherwise omit `--ticket` and let the script derive the task identity. Run it from the checkout where the solved work occurred:

```bash
SKILL_DIR="<absolute path of the directory containing the SKILL.md you just read>";
PY="$(for c in python3 python py; do command -v "$c" >/dev/null 2>&1 && "$c" -c 'import sys; sys.exit(sys.version_info < (3, 9))' >/dev/null 2>&1 && { echo "$c"; break; }; done)"; [ -n "$PY" ] || { echo "no working Python 3.9+ interpreter on PATH" >&2; exit 1; };
"$PY" "$SKILL_DIR/scripts/prepare-worktree.py" prepare
```

Append `--ticket "$TICKET"` only when `TICKET` holds the validated ID. The script must be present and return JSON with `worktree`, `branch`, `source_root`, `source_branch`, `source_dirty`, `partial_outputs`, and `pending_writes`. A missing script, missing Python/Git, nonzero exit, or malformed result is a hard stop: report its recovery guidance. In non-interactive mode, end the failure report with `Documentation skipped`; do not ask a question or write a doc. Never substitute an unverified checkout, stash, reset, or remove a worktree.

Use the returned `worktree` as the working directory for documentation and code-grounding reads, validation, and writes; verify each new shell/tool invocation uses that directory because shell `cd` does not persist across calls. Pass its absolute path to every research subagent as the sole project root. Keep `source_root` and `source_branch` for read-only session-history discovery and source-versus-destination comparison. Verify that the solved fix's defining commit or code is present in `worktree` before writing, even when `source_dirty` is false. If `source_dirty` is true and the learning depends on source-only uncommitted changes, stop and explain that the user can commit the fix and retry; leave those changes intact. A retry after that commit must include it in the owned branch; the helper blocks stale reuse until it does. If `partial_outputs` is nonempty, read those product files before continuing the same learning. If `pending_writes` is nonempty, recreate the intended scratch draft and retry the recorded write instead of creating a duplicate.

For **each** product write, first create the complete replacement content in private scratch (`{run_dir}` in Full mode, an OS temp draft in Lightweight). From `worktree`, run `allow-write --path <repo-relative-file>` immediately before the edit, then `commit-write --path <same-file> --input <absolute-scratch-file>` using the same bundled Python script and selected interpreter. Proceed only when both exit 0; never edit the product path directly. This includes a solution document, `CONCEPTS.md`, a consented instruction-file edit, `.compound-engineering/config.yaml`, and any in-tree pack rule. Each path must resolve inside the prepared worktree; external pack destinations are unavailable in this run. The helper records the file's pre-write state and expected result before replacing it atomically. On interruption, retrying `commit-write` with the same draft is safe; an unrelated edit blocks. Re-run `prepare` before a later sequential learning and follow the same check.
