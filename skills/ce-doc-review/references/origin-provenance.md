# Verify document provenance and scope

Extract the raw upstream source once: prefer `origin:` when present, otherwise use `product_contract_source:<value>`, otherwise `none`. Then resolve an authoritative `Origin provenance:` state. A path shape or metadata marker alone is not proof of validation.

| Raw source | Independently verifiable check | `Origin provenance:` |
|---|---|---|
| `none` | No upstream Product Contract claimed | `greenfield` |
| `product_contract_source:ce-plan-bootstrap` | Bootstrap is intentionally greenfield | `greenfield` |
| `product_contract_source:ce-brainstorm` or `product_contract_source:legacy-requirements` on a unified artifact | First require a Product Contract slice that classifies as requirements. Then verify lineage outside the artifact under review: either the current-session handoff proves this exact Product Contract was accepted before enrichment, or repository history contains a requirements-only revision whose Product Contract IDs and substantive text match, with independent evidence that this revision was accepted. The source marker and current slice cannot attest themselves. | `validated` only with matching external lineage; `source-present` when the slice is requirements-shaped but lineage is unverified; otherwise `unresolved` |
| Legacy `origin:` path | Resolve absolute paths directly and relative paths from the reviewed document's repository/worktree root; read and classify the target. Readability and requirements shape prove source presence only. Validation additionally requires current-session evidence that the upstream contract was reviewed/accepted, or an explicit review attestation from a separate trusted artifact. | `validated` with independent acceptance evidence; `source-present` when readable and requirements-shaped without that evidence; otherwise `unresolved` |
| Any other value, including a source marker on a legacy plan with no inspectable Product Contract | No independently inspectable upstream contract | `unresolved` |

Record the decisive external evidence in `Provenance evidence:` as `session-handoff:<reference>`, `requirements-revision:<reference>`, or `trusted-attestation:<reference>`, or `none`. Never stop the review because an upstream source is missing. `source-present` and `unresolved` are conservative review states: both activate and route premise-level techniques as greenfield while reporting traceability only when it creates a concrete defect. Requirements shape proves that a source exists; it never proves the premises were validated.

When a plan has `Origin provenance: validated`, compare its proposed actors, user-visible flows, requirements, and restored deferred items against the validated Product Contract. Set `Scope extension:` to a compact semicolon-separated list of explicit additions, or `none`. Each entry names the plan item or quote and the upstream boundary it exceeds. Do not classify file decomposition, technical assumptions, architecture, sequencing, tests, rollout mechanics, or other implementation detail as product-scope extension. This slot identifies only additions; inherited decisions remain validated. If provenance is `greenfield`, `source-present`, or `unresolved`, set `Scope extension: none` because the entire plan already receives greenfield scrutiny.

For a relative legacy path, if no repository/worktree root can be established or the target cannot be resolved beneath the review workspace, use `unresolved`; never guess a different base directory. Do not stop the review because an upstream artifact is unresolved.
