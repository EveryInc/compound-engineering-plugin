Design a non-executable approach for resumable upload intake. Existing system has one PostgreSQL database, two stateless API replicas, and object storage. Clients upload files up to 2 GB on flaky mobile links; retries may overlap; metadata commits must never expose an incomplete object. Object storage and database cannot participate in one transaction. No new queue service, no sticky sessions, no browser-held secret credentials. Tenant isolation is mandatory. Product decisions are settled: eventual upload completion is acceptable; visible duplicate documents are not. Compare meaningful mechanisms for retries, idempotency, publication, and cleanup. Do not implement code. Cite these local constraints.
