Given that the reconciliation job, which is scheduled hourly but can also be triggered manually via the admin console (subject to the operator holding the finance role), compares the ledger snapshot against the payment provider's settlement export and, where a discrepancy exceeding 0.5 percent of the batch total is detected, both halts further settlement for that merchant and opens a ticket in the operations queue tagged with the batch id, it follows that any change to the export format necessitates a corresponding update to the parser as well as to the threshold configuration, which lives in a separate file.
